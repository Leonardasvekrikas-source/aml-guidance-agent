# aml-guidance-agent

A retrieval-augmented agent that answers questions about AML typologies and
regulatory expectations, grounded in public guidance documents — and refuses when
the corpus doesn't support an answer.

Built to be run by a stranger: `docker compose up`, then one command to reproduce
every number below.

> **Status:** in progress. Numbers below are filled in as milestones land; nothing
> is claimed here that isn't reproducible from `make eval`.

---

## Why this exists

Most retrieval systems are evaluated on whether they return something plausible.
In a regulated domain that is the wrong bar — a fluent answer citing a regulation
that doesn't say what the answer claims is worse than no answer at all.

This project takes the opposite approach:

1. **The retrieval layer is benchmarked, not assumed.** Lexical, dense and hybrid
   retrieval are compared on a hand-authored evaluation set with known correct
   passages.
2. **Citations are verified in code, not by the model.** Every claim the agent
   makes must trace to text that was actually retrieved. Unverifiable claims are
   rejected before the answer is returned.
3. **The evaluation set contains questions the corpus cannot answer.** A system
   that scores well on answerable questions and bluffs on the rest has not been
   evaluated.

## Architecture

```
question
   │
   ▼
┌─────────────────────────────────────────────┐
│  agent loop (hand-written, no framework)    │
│  • decides whether to search again          │
│  • reformulates on weak results             │
│  • hard cap on iterations                   │
│  • may return "insufficient evidence"       │
└──────────────┬──────────────────────────────┘
               │  search(query, k)
               ▼
┌─────────────────────────────────────────────┐
│  hybrid retrieval                           │
│  BM25 ∪ pgvector, fused with RRF            │
└──────────────┬──────────────────────────────┘
               │  chunks + provenance
               ▼
┌─────────────────────────────────────────────┐
│  drafting                                   │
│  answer written only from retrieved chunks  │
└──────────────┬──────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────┐
│  validation  ← the point of the project     │
│  every citation checked against retrieved   │
│  text; unsupported claims reject the draft  │
└──────────────┬──────────────────────────────┘
               │
               ▼
      answer + citations, or refusal
```

**No agent framework.** The loop is a few hundred lines of plain Python. This is
deliberate: LangChain or LlamaIndex would hide the two things this project is
actually about — when the loop decides to stop, and what happens to a claim that
fails validation. Both are explicit here and can be read top to bottom.

## Stack

| Layer | Choice | Why |
|---|---|---|
| Store | PostgreSQL 16 + pgvector | One database for lexical metadata, chunks and embeddings. No second service to run. |
| Lexical retrieval | `rank_bm25` over the chunk set | Real BM25 on a corpus small enough to hold in memory. Honest to describe as BM25, unlike Postgres `ts_rank`. |
| Dense retrieval | `bge-base-en-v1.5` via sentence-transformers | Runs locally on the RTX 4090. No API cost per experiment, so re-running the benchmark is free. |
| Fusion | Reciprocal Rank Fusion | Standard, no tuning, no training. |
| Generation | Anthropic API | Reliability over local for the drafting step; the embedding side is where local matters. |
| Service | FastAPI | One `/ask` endpoint. |
| Deployment | Docker Compose | App + Postgres. `docker compose up` is the whole setup. |

## Corpus

Public regulatory and typology guidance only. Every document is recorded in
`corpus/manifest.yaml` with source URL, publisher, publication date and retrieval
date. Nothing is committed that isn't publicly downloadable.

Target: 20–30 documents drawn from FATF typology and guidance reports, EBA ML/TF
risk factor guidelines, FinCEN advisories, Wolfsberg Group papers and Europol
threat assessments.

## Running it

```bash
git clone <repo> && cd aml-guidance-agent
cp .env.example .env          # add ANTHROPIC_API_KEY
docker compose up -d
make ingest                   # download corpus, chunk, embed, load
make eval                     # regenerate every number in this README
make serve                    # FastAPI on :8000
```

```bash
curl -X POST localhost:8000/ask \
  -H 'content-type: application/json' \
  -d '{"question": "What indicators suggest trade-based money laundering in invoice documentation?"}'
```

## Limitations

Written honestly, and kept current.

- The evaluation set is authored by one person. It reflects one analyst's view of
  what a correct answer looks like, and inter-annotator agreement is unmeasured.
- Groundedness is scored by an LLM judge. Judge–human disagreement is measured on
  a sample and reported in `results/judge_agreement.md` rather than assumed away.
- The corpus is guidance, not case law or enforcement actions. Questions about
  specific enforcement outcomes are out of scope by construction.
- Retrieval is over English-language documents only.
- This is a portfolio system, not a compliance tool. It has no place in a real
  reporting workflow.
