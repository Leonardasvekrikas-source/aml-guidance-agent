# What broke

Failures are logged here rather than silently fixed. Each entry says what
happened, why, and what changed as a result.

---

## M0 — `docker compose up` failed on a clean clone

**Symptom.** `docker compose config` refused to parse:

```
env file /path/to/.env not found
```

**Cause.** The `app` service declared `env_file: .env`, which Compose treats as
required. On a fresh clone `.env` does not exist — the README tells you to copy
`.env.example` first, but `docker compose up` is the command people actually
run first.

**Why it matters.** The stranger test for this repo is "clone it, follow the
README, get an answer in ten minutes". A hard failure on the first command
fails that test regardless of what the rest of the system does.

**Fix.** `env_file` is now declared with `required: false`. The stack comes up
without a `.env`; retrieval and the M1 benchmark work, and only the steps that
call the Anthropic API fail, with a clear error rather than a parse failure.

---

## M0 — published Postgres port collided with an unrelated project

**Symptom.**

```
Bind for 0.0.0.0:5433 failed: port is already allocated
```

**Cause.** 5433 was chosen to avoid the usual host Postgres on 5432, but
another container on the development machine had already taken it.

**Why it matters.** Nothing about the application was wrong — the app reaches
the database as `db:5432` on the Compose network and never touches the
published port. Only the host-side binding collided. This is the practical
difference between the two addresses, and it is worth stating plainly because
it is the thing most often misunderstood about Compose networking.

**Fix.** The published port moved to 5434 and is now overridable via
`POSTGRES_HOST_PORT` in `.env`, so the next collision is a one-line change
rather than an edit to `docker-compose.yml`.

---

## M0 — the documented `make` targets could not run on Windows

**Symptom.** `make: command not found` on the development machine.

**Cause.** The README documented a `make`-based workflow. `make` is not present
on a default Windows install, and this project is developed on Windows.

**Why it matters.** Every number claimed in the README is supposed to be
regenerated by a committed script. If the documented entry point does not run
on the machine the author uses, that guarantee is theoretical.

**Fix.** `run.ps1` mirrors every Makefile target with the same names. The
Makefile stays for Linux and macOS. Both are committed and both are documented.
